> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship 5 Siri voice intents (Resume, Pause, Next chapter, Previous chapter, Play by name) for the Abbay audiobook app, conforming to `AudioPlaybackIntent` (iOS 17+), without foregrounding the UI on voice commands.

**Architecture:** All intent code in the existing `Abbay` app target. No new framework, no extension, no App Group. State lives in: existing `DependencyContainer.shared.player`, existing `LoadAllAudiosUseCase` / `LoadAudioUseCase`, and a new tiny `LastPlayedStore` over `UserDefaults.standard`. Spec: `docs/superpowers/specs/2026-05-16-siri-design.md`.

**Tech Stack:** Swift 5, `AppIntents` (iOS 17+), `AudioPlaybackIntent`, `AVFoundation`, existing Core Data stack, XCTest, xcodegen, xcodebuild.

```swift
//  LastPlayedStore.swift

import Foundation

/// Persists the URL of the most-recently-played audiobook so that
/// Siri's "Play in Abbay" / "Resume Abbay" intents can resume it.
///
/// Single-process v1; `UserDefaults.standard`. Phase-2 migration to
/// App Group `UserDefaults` is documented in the design spec.
enum LastPlayedStore {
    private static let lastPlayedKey = "abbay.lastPlayedAudioURL"

    /// Injection point for tests. Production reads/writes `.standard`.
    static var defaults: UserDefaults = .standard

    static func save(url: URL?) {
        defaults.set(url?.absoluteString, forKey: lastPlayedKey)
    }

    static func lastPlayedURL() -> URL? {
        guard let string = defaults.string(forKey: lastPlayedKey) else { return nil }
        return URL(string: string)
    }
}
```

```swift
//
//  AbbayIntents.swift
//  Abbay
//

import AppIntents
import Foundation

// MARK: - Fuzzy match helper

/// Returns the best library match for a spoken title, or nil if no audio scores > 0.
///
/// Scoring (after `normalize`):
///   3 — exact equality
///   2 — title starts with input
///   1 — title contains input
///   0 — no overlap (filtered out)
///
/// Tie-break: an audio whose `url` equals `lastPlayedURL` is preferred over library order.
func fuzzyMatch(input: String,
                audios: [AudioModel],
                lastPlayedURL: URL?) -> AudioModel? {
    let q = normalize(input)
    guard !q.isEmpty else { return nil }

    struct Scored {
        let audio: AudioModel
        let score: Int
        let isLastPlayed: Bool
        let index: Int
    }

    let scored: [Scored] = audios.enumerated().compactMap { idx, audio in
        let t = normalize(audio.title)
        let score: Int
        if t == q { score = 3 }
        else if t.hasPrefix(q) { score = 2 }
        else if t.contains(q) { score = 1 }
        else { score = 0 }
        guard score > 0 else { return nil }
        return Scored(audio: audio,
                      score: score,
                      isLastPlayed: audio.url != nil && audio.url == lastPlayedURL,
                      index: idx)
    }

    return scored.max { a, b in
        if a.score != b.score { return a.score < b.score }
        if a.isLastPlayed != b.isLastPlayed { return !a.isLastPlayed && b.isLastPlayed }
        return a.index > b.index
    }?.audio
}

/// Normalization for fuzzy-match comparison. Order is load-bearing:
///   1. Replace "&" with " and " (before stripping, otherwise & is lost)
///   2. Lowercase
///   3. Strip CharacterSet.punctuationCharacters ∪ .symbols
///   4. Collapse whitespace runs to a single space
///   5. Trim
private func normalize(_ s: String) -> String {
    var out = s.replacingOccurrences(of: "&", with: " and ")
    out = out.lowercased()
    let stripped = CharacterSet.punctuationCharacters.union(.symbols)
    out = String(out.unicodeScalars.filter { !stripped.contains($0) })
    let parts = out.split(whereSeparator: { $0.isWhitespace })
    return parts.joined(separator: " ")
}
```

## Task 7: (removed) `AudioEntity` and `AudioEntityQuery`

**No code in this task.** Records a design decision discovered during plan review.

v1 does **not** introduce `AudioEntity` / `AudioEntityQuery`. `PlayBookByNameIntent` takes a `String` parameter (the raw spoken phrase) and runs `fuzzyMatch` inside `perform()`. Rationale:

- `AudioEntityQuery.entities(matching:)` resolves the parameter **before** `perform()` runs. When the query returns `[]`, the AppIntents framework speaks its own canned no-match dialog, not the spec-locked `"No audiobook matches '\(input)'."`. With a `String` parameter, `perform()` always runs and can speak the spec dialog with the input echoed.
- Spec-locked decisions explicitly defer disambiguation (non-goal). Singleton-or-empty entity matching offered no value over a direct `String` parameter while losing the no-match dialog and the input echo.
- Suggested-entities surfacing in Siri shortcut UI is also a non-goal for v1.

The `String`-parameter shape is implemented in Task 12 (`PlayBookByNameIntent`). No file changes in this task. Skip to Task 8.

```swift
// MARK: - Play book by name

struct PlayBookByNameIntent: AudioPlaybackIntent {
    static let title: LocalizedStringResource = "Play audiobook in Abbay"
    static let description = IntentDescription("Plays a specific audiobook in Abbay by name.")

    @Parameter(title: "Audiobook", requestValueDialog: IntentDialog("Which audiobook?"))
    var bookName: String

    init() {}

    // Spec-locked dialog text. v1 ships English only (non-goal: localization).
    // Lift into constants so a unit test catches regressions on wording / punctuation.
    static func noMatchDialog(_ input: String) -> String {
        "No audiobook matches '\(input)'."
    }
    static let cannotFindDialog = "Cannot find that audiobook. It may have been removed or is not downloaded."
    static func playingDialog(title: String) -> String {
        "Playing \(title)."
    }

    @MainActor
    func perform() async throws -> some IntentResult & ProvidesDialog {
        let library = DependencyContainer.shared.loadAllAudios.execute()
        let lastPlayed = LastPlayedStore.lastPlayedURL()
        guard let hit = fuzzyMatch(input: bookName, audios: library, lastPlayedURL: lastPlayed),
              let url = hit.url else {
            return .result(dialog: IntentDialog(stringLiteral: Self.noMatchDialog(bookName)))
        }
        guard var model = DependencyContainer.shared.loadAudio.execute(url: url) else {
            // Stuck-state guard: clear pointer only if the dead match is the saved one.
            if LastPlayedStore.lastPlayedURL() == url {
                LastPlayedStore.save(url: nil)
            }
            return .result(dialog: IntentDialog(stringLiteral: Self.cannotFindDialog))
        }
        DependencyContainer.shared.player.play(&model)
        return .result(dialog: IntentDialog(stringLiteral: Self.playingDialog(title: model.title)))
    }
}
```

- [ ] **Step 3: Manual checks — playback control**

In order, perform each check. Note any deviation from expected behavior; deviations are spec failures, not test failures, and should be raised on the PR.

  - Add an audiobook. Play it. Background the app. Say **"Hey Siri, pause Abbay"**. Expected: playback pauses, Now Playing reflects paused state, Siri speaks "Paused."
  - Say **"Hey Siri, next chapter in Abbay"**. Expected: player advances to next chapter, Siri speaks "Next chapter."
  - Say **"Hey Siri, previous chapter in Abbay"**. Expected: player rewinds per the existing `>15s` rule in `Player.skipToPreviousChapter`, Siri speaks "Previous chapter."
  - Kill the app. Say **"Hey Siri, play in Abbay"**. Expected: app launches into background audio context (UI does NOT come to foreground), resumes the last book at saved position, Siri speaks `"Playing \(title)."`

- [ ] **Step 4: Manual checks — failure modes**

- [ ] **Step 6: Documented v1 failure mode — cold-launch-during-call (all five intents)**

The cold-launch failure comes from `AppDelegate.application(_:didFinishLaunchingWithOptions:)` activating `AVAudioSession`. That path runs on **every** cold launch — so cold-launch-during-call affects all five intents (Resume, Pause, NextChapter, PreviousChapter, PlayBookByName), not just Resume.

Primary verification: kill the app. Start an active phone call (or place the device on an active FaceTime audio call). Say **"Hey Siri, play in Abbay"**. Expected v1 outcome: the app does not start playback. Verify the documented crash by inspecting the device console (`Console.app` → connect device → filter on `Abbay`) for the `AVAudioSession` `setActive` throw and the matching `fatalError`.

Spot-check at least one additional intent (e.g. "Hey Siri, pause Abbay" with the app killed and a call active) to confirm the failure mode is shared, not Resume-specific. This is the spec's accepted v1 behavior — phase 2 replaces it with a spoken "audio temporarily unavailable" dialog for all five intents.
